# 需求规格说明书（Requirements Specification）

> 项目：表格数据 + LLM 融合的企业智能分析 Agent
> 版本：v1.0 · 编写：成员A / 成员C

## 1. 引言

### 1.1 编写目的
明确本系统应交付的功能/非功能需求，作为设计、开发、测试与验收的依据。

### 1.2 项目背景
见《任务书》与《项目提案》。核心：让用户以自然语言对上传的表格进行分析，系统自动完成理解→计划→代码执行→图表→结论，支持追问、假设检验、留痕与报告导出，并具备企业级权限、脱敏与审计。

### 1.3 读者对象
开发人员、测试人员、项目干系人、课程指导教师。

### 1.4 术语定义
| 术语 | 定义 |
|:---|:---|
| Agent | 具备"计划-执行-反思"能力的分析代理 |
| Schema 画像 | 表格结构化的语义描述（列类型/示例值/空值率/基数等） |
| 沙箱 | 受限的可执行代码环境 |
| what-if | 假设检验，修改条件重新对比分析 |

## 2. 用户需求

### 2.1 用户角色
- 业务人员：上传数据、自然语言提问、查看结论与图表、导出报告、追问。
- 数据分析师：深入探索、假设验证、查看生成的代码（可复现）。
- 企业管理员：配置权限/脱敏、查看审计。

### 2.2 用户故事（优先级 P0/P1）
| 编号 | 用户故事 | 优先级 |
|:---|:---|:---:|
| US-01 | 上传 Excel/CSV 并用自然语言提问，获得数据洞察 | P0 |
| US-02 | 支持多表上传与自动关联（跨表分析） | P0 |
| US-03 | 看到"问题→代码→结果→图表→结论"全过程（可信、可复现） | P0 |
| US-04 | 追问上一轮结果（"剔除某区域会怎样"） | P0 |
| US-05 | 一键导出分析报告（docx/pdf） | P1 |
| US-06 | 管理员配置字段级权限与敏感列脱敏 | P1 |
| US-07 | 管理员查看全部分析审计（谁/何时/问了什么/跑了什么代码） | P1 |
| US-08 | 百万行 CSV 查询响应 < 3 秒 | P1 |

## 3. 功能需求

### FR-1 表格上传
- 支持 .csv/.xlsx/.xls；流式写入；返回 table_id、行列数。
- 上限：单文件 ≤200MB、单表 ≤100 万行。

### FR-2 Schema 画像
- 生成列类型、示例值、空值率、基数；多表推断关联键注入 Prompt。

### FR-3 分析闭环
- 计划 → 代码生成 → 沙箱执行 → 结果检查 → 失败反思重试（≤3轮）→ 图表与结论。

### FR-4 图表与报告
- 按数据特征自动选图（趋势→折线、占比→饼、对比→柱）；报告导出 docx/pdf，图表可溯源。

### FR-5 追问与假设检验
- 会话上下文保持；极简追问补全；what-if 重算。

### FR-6 多表关联
- 自动发现共同列，merge 为宽表供跨表分析。

### FR-7 企业安全
- 敏感列识别脱敏；字段级权限；审计留痕（分页查询）。

## 4. 非功能需求
- **性能**：百万行查询 <3s；代码一次通过率≥70%（反思后≥90%）。
- **安全**：沙箱禁网络、限资源，逃逸拦截 100%；敏感信息脱敏。
- **可用性**：自然语言交互，中文界面与结论。
- **可维护性**：模块化、全量中文注释、配置化（.env）。
- **可复现性**：分析过程留痕，报告含可执行代码。

## 5. 约束
- 语言：Python + TypeScript；框架：FastAPI、LangGraph、React、DuckDB、ECharts。
- 模型：DeepSeek API + Ollama 本地兜底。
- 交付：系统 + 设计报告 + 演示数据，全部代码中文注释。

## 6. 验收标准（对照选题）
端到端正确率≥85%、代码一次通过率≥70%（反思后≥90%）、百万行查询<3s、沙箱逃逸拦截100%、报告导出格式规范且图表数据 100% 可溯源复现。
